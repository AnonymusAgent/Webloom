# Webloom improvement handoff — 2026-10-19

The initial handoff measurements and 3D description below are historical; the follow-up section records the current implementation.

## Implemented

- Preserved the existing App Router pages, service descriptions, website tiers ($299 / $599 / $1,199), GitHub work, administration, PostgreSQL lead storage, and email-on-lead-decision integration.
- Kept the existing brand and homepage sections while making the hero copy and actions visible in initial HTML; replaced the animated route transition and full-screen loading UI with immediate content/brief loading text. Below-the-fold content no longer waits for scroll animation to become visible. The optional 3D hero loads only on fine-pointer desktop devices, on idle, and never for reduced-motion visitors.
- Self-hosted Inter and JetBrains Mono with `next/font/local` and `font-display: swap`; only Inter preloads. This also removes the Google Fonts network dependency from production builds.
- Added dedicated, clearly labeled `/work/[slug]` product pages for BloomPOS, Noor, Pulse and Clarity Health; retained the original `/work#...` anchors. Concepts are described as concepts, not customer case studies or launched products. No unverified screenshots, metrics or testimonials were introduced.
- Added shared page-specific title, description, canonical and OG/Twitter metadata to public pages, product pages and articles. The existing Organization schema now accompanies WebSite schema; JSON-LD is HTML-script escaped before insertion. The sitemap includes product routes and excludes legal draft templates; the templates remain publicly accessible with `noindex`. Existing robots, FAQ schema and blog URL structure are preserved.
- Improved mobile navigation focus management, Escape handling, touch targets and small-screen menu scrolling. Form validation now announces an error summary, and submissions include a honeypot and a small request size limit. Successful database inserts record a privacy-safe conversion event; unsuccessful requests return an error and do not show a success confirmation.
- Updated Next.js and its lint tooling to 16.4.2 and the direct PostCSS dependency. `npm audit --omit=dev` reports **0 production dependency advisories**. Added `npm run test:smoke` for production-mode HTTP/SEO and invalid-form checks.

## Follow-up: progressive motion, loading order and AR Manager — 2026-10-20

The byte counts and "static wrapper" descriptions above are historical and **do not measure this iteration**. The current code restores Framer Motion reveals and uses a small CSS first-paint hero stagger, a five-step workflow, the source-backed technology section as static cards, fine-pointer-only card depth and scroll reveals across sections, FAQ and footer. Motion is one-shot; the server HTML and above-the-fold content remain visible even without hydration. Reduced-motion mode skips reveal preparation, and there is no render loop, WebGL scene, cursor follower or scroll hijack.

**Root cause reproduced in a cold development navigation:** Next's root `loading.tsx` was rendered inside `<main>` while the shared client `Chrome` rendered `<Footer>` immediately after it. At DOMContentLoaded the loading main was 212px high and the footer started at 212px in a 900px viewport; after the route streamed, the footer moved past 9,000px. `#main { min-height: 100svh; }` now gives the loading main real document flow height. It does not hide, delay or reposition the footer; it keeps the footer after a full viewport of loading content, then the rendered route replaces the loading content. The database-dependent home sections still stream separately and may insert content when available.

**AR Manager provenance:** the public `AnonymusAgent/AR-Manager` repository contains a TypeScript/Next.js medical-billing AR platform, including dashboard statistics for claims, pending reviews, billing, claims by status and assignees, and routes for payments, patients and authorizations. No real product screenshots were found in its repository. `public/images/projects/ar-manager.svg` is an explicitly captioned *source-informed illustration, not a screenshot*; it contains no patient data or purported metrics. Seed data now uses the correct category, stack and summary. Legacy database rows are corrected at read time for known incorrect fields and a missing/old image, without changing the DB schema or connection. The GitHub source URL remains intact. A live database-backed AR Manager card could not be inspected in this sandbox.

**Verification:** production `npm run build`, `npm run lint`, `npm run typecheck`, and `npm run test:smoke` passed with a placeholder local DB URL and a public canonical origin supplied via environment variables only. Headless Chromium browser checks against the production preview passed at 1440×900 and 390×844, with and without `prefers-reduced-motion`: hard reload/initial footer position, hero/workflow and overflow checks, downward and upward scroll reveal behavior, seven additional route reloads, pricing tab activation, mobile menu/Escape and AR illustration HTTP delivery. The production static routes and invalid contact requests passed HTTP smoke; **database-backed posts, testimonials, project cards, live lead submission/email and real-user Core Web Vitals remain unverified** because this sandbox has no configured live database or field browser telemetry. No production database settings or secrets were modified.
